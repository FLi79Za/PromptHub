# Knowledge Import Policy

## Accept

Import a finding when it materially changes model selection, prompt structure, supported modes, reference handling, editing practice, text rendering, output controls or realistic 16 GB viability.

## Evidence hierarchy

1. Official model documentation
2. Official repository
3. Official model card
4. Reproducible community evidence, clearly labelled

Prefer a newer official source over an older one. Preserve the date and canonical URL. Do not convert an inference into an official claim.

## Reject

- Marketing without actionable prompting impact
- Duplicate or paraphrased existing guidance
- Prompt folklore without a model-specific source
- Benchmark movement without workflow relevance
- Generic quality-token lists
- Unsupported negative prompts or camera tokens
- Runtime claims that omit precision, resolution or offload context

## Resolve conflicts

Record the new entry, mark its confidence, and revise the stable model reference only when the newer evidence clearly supersedes it. Retain mode- or version-specific distinctions instead of flattening them into a universal rule.
